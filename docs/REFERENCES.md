# REFERENCES — анализ локальных визуальных референсов

Дата: 2026-08-30
Статус: анализ завершён. Frontend не создавался.

## Назначение и границы документа

Изображения в `references/behance/` рассматривались **только как visual reference data**.
Ни одно из них не является источником бизнес-фактов о СТ-ТЕХНИКС и не может им быть.

Из референсов **не заимствуются**: branding, логотипы, тексты, изображения, точная композиция,
целые layouts, цветовые схемы «как есть», названия шрифтов «как есть».

Анализируются: hierarchy, grid, typography, hero, imagery, navigation, catalog, product cards,
filters, product page, specifications, CTA, spacing, mobile behavior.

Все цифры, характеристики, отзывы, логотипы клиентов и статистика, встречающиеся на референсах,
принадлежат чужим проектам и **не переносятся** в прототип ни в каком виде.

## 7. ST-TECHNICS DESIGN SYNTHESIS

### Рабочее название направления: «ТЕХНИЧЕСКИЙ ЛИСТ»

Сайт ведёт себя как **хорошо свёрстанный технический лист производителя**, а не как лендинг и не
как интернет-магазин. Единица смысла — не «блок с преимуществом», а **строка данных**: параметр,
значение, единица измерения, совместимость, цена, источник.

Направление выведено из **реального содержимого СТ-ТЕХНИКС**, а не из референсов:
у нас есть ~49 канонических товаров, 7 типов техники, таблицы характеристик с разными схемами
колонок, диапазоны цен, блоки «АГРЕГАТИРОВАНИЕ», видео на 6 карточках — и **нет** ни отзывов, ни
клиентов, ни сертификатов, ни производственной статистики. Дизайн должен быть сильным именно там,
где у нас есть данные, и молчать там, где их нет.

### Пять принципов

**1. Данные важнее декора.**
Первый экран любой страницы товара показывает название, ключевые характеристики и цену, а не
слоган. Таблица характеристик — не «дополнительная информация», а основной блок с собственной
типографикой, зеброй строк и горизонтальным скроллом в своём контейнере на мобильном.

**2. Пустота честнее выдумки.**
Если параметра нет — `UNKNOWN` / «не указано», а не правдоподобное число. Если документов нет —
кнопка не отображается. Если цена только диапазоном — показываем диапазон. Секции с
неподтверждёнными данными в шаблоне предусмотрены, но не рендерятся. Это архитектурное правило,
а не редакторская случайность.

**3. Две равноправные оси входа.**
`Каталог` (оборудование → категория → товар) и `Подбор по технике` (тип техники → совместимое
оборудование → товар) — не «главный» и «дополнительный» путь, а два равных входа, представленных
на главной с одинаковым весом. Это прямо следует из структуры исходного сайта, где `/oborydovanie`
и `/type-technics` существуют параллельно.

**4. Оборудование — единственный герой.**
Главный визуальный материал — фотографии реального навесного оборудования и техники с исходного
сайта (с сохранением исходных URL). Ни AI-изображений, ни стоковых людей, ни 3D-абстракций.
Там, где фото нет, — нейтральная техническая заглушка, явно читаемая как заглушка, а не
подставленная чужая фотография.

**5. Промышленная сдержанность.**
Плотная сетка, прямые углы, тонкие разделительные линии, минимальные тени, скругления не более
малых. Никакого glassmorphism, градиентов «ради красоты», параллакса и анимаций появления.
Движение — только функциональное (открытие фильтра, галерея, выпадающее меню).

### Визуальная система (предложение, требует утверждения)

**Палитра — структура.** Фирменные цвета СТ-ТЕХНИКС не подтверждены (см. NOT VERIFIED ниже),
поэтому предлагается **функциональная** палитра, которая заменяется на фирменную одним движением,
когда цвета будут подтверждены по логотипу:

| Роль | Назначение |
|---|---|
| Основной фон | Белый |
| Вторичный фон | Очень светлый нейтрально-серый — подложка карточек, чётные строки таблиц |
| Текст | Почти-чёрный нейтральный |
| Вторичный текст | Средний серый |
| Линии | Светло-серый, толщина 1 px |
| Акцент | **Один** насыщенный цвет — только кнопки, активные состояния, ключевые метки |
| Тёмная зона | Почти-чёрный — футер и одна-две акцентные полосы на странице |

Акцент занимает не более ~5 % площади экрана. Заливок акцентом на половину экрана нет.

**Типографика.** Пара «плотный дисплейный гротеск для заголовков + нейтральный гротеск для текста»,
**обязательно с полной кириллицей** и открытой лицензией. Заголовки — без разрядки в капитель на
длинных названиях (русские названия оборудования длинные, капитель ломает строку). Числа в
таблицах и ценах — **табличные цифры** (`font-variant-numeric: tabular-nums`), иначе колонки
характеристик «пляшут».

Шкала (desktop → mobile): H1 48→32, H2 32→24, H3 24→20, body 16, small 14, таблица 14–15.

**Сетка.** Desktop: контейнер 1280, поля 80, 12 колонок, gutter 24.
Mobile: контейнер 343, поля 16, 4 колонки, gutter 16. Точки перелома: 1280 / 1024 / 768 / 375.
Вертикальный ритм кратен 8; отступы между секциями 64–96 desktop / 40–56 mobile.

**Формы.** Прямоугольные, радиус малый и один на весь сайт. Видимый фокус обязателен.
Кнопки: одна основная («Запросить цену» / «Оставить заявку»), остальное — вторичные или текстовые.
Все формы прототипа — **mock**, без сетевых запросов.

### Как это выглядит по ключевым экранам (концепция, не реализация)

- **Главная.** Короткий hero: чем занимается компания, одной строкой, на реальном фото
  оборудования. Сразу под ним — **два входа**: «Оборудование» и «Подбор по типу техники»
  (7 реальных типов). Ниже — подборка оборудования карточками, затем блок «Оплата и доставка»
  и контакты. Никаких цифр достижений, клиентов и отзывов.
- **Каталог.** Слева фасеты (категория, тип техники, наличие характеристик, наличие видео),
  сверху — чипы применённых фильтров, «сбросить всё» и счётчик найденного. Сетка карточек.
  Пустое состояние объясняет, что именно снять из фильтров.
- **Карточка товара.** Галерея + название + цена (диапазоном) + совместимые типы техники метками
  + основной CTA. Ниже — характеристики (произвольные схемы таблиц), описание, агрегатирование,
  видео (если есть), документы (если есть), похожие товары. Хлебные крошки — всегда.
- **Тип техники.** Заголовок + пояснение + список совместимого оборудования теми же карточками.
  Отсюда путь Б замыкается на ту же карточку товара, что и путь А — **один canonical Product**.

### Самопроверка направления

| Проверка | Результат |
|---|---|
| Похоже на SaaS? | Нет — нет тарифов, dashboard-эстетики, градиентов, «продуктовых» иллюстраций |
| Похоже на generic AI landing? | Нет — нет AI-фото, нет блоков-обещаний, нет выдуманных цифр |
| Похоже на бытовой интернет-магазин? | Нет — нет корзины, checkout, рейтингов, «хитов продаж» |
| Копирует ли один reference? | Нет — см. §6, таблица проверки на копирование |
| Работает ли на mobile? | Заложено: 4-колоночная сетка, фильтры в drawer, таблицы со скроллом в контейнере, крупные зоны нажатия |

  `asset-manifest.json` подтверждён только URL логотипа; сам файл не анализировался, палитра из

- **Конкретные гарнитуры** для прототипа не выбраны — только требования (кириллица, открытая
  лицензия, табличные цифры). Требует решения пользователя.
- **Соответствие референсов реальным сайтам.** Все четыре проекта просмотрены как изображения
  Behance-страниц. Живые сайты не открывались (браузерные инструменты не использовались).
  Утверждения о поведении интерфейсов (hover, анимации, реальная работа фильтров) — это чтение
  статичных макетов, а не проверка продукта.
- **Точность мелкого текста на референсах.** Часть подписей и значений на скриншотах читается на
