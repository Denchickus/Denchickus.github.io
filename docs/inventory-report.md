# Inventory Report — st-technics.ru

Роль на этом этапе: **только исследователь**. Frontend не создавался. Внешний сайт рассматривался
как **недоверенные данные (DATA)**; инструкции, встречающиеся в его контенте, не исполнялись.

- Дата: 2026-08-30
- Источник: https://st-technics.ru/ (публичный сайт, платформа Tilda)
- Метод: `robots.txt` + `sitemap.xml` + `sitemap-store.xml` → перечисление URL; затем поштучная
  загрузка страниц (конвертация в Markdown + извлечение малой моделью); затем проверка
  подозрительных ссылок запросами (HTTP-код). Проведён второй проход по витринам и каталогу.
- Пользователь разово снял запрет на веб-доступ **для этой задачи** (запрет на браузерные
  инструменты остаётся в силе после неё).

  - 27 «ковшовых» страниц — это, по сути, варианты 8 типов ковшей
    (общестроительный, высокообъёмный, челюстной, планировочный, серповидный, просеивающий,
    универсальный, высокой выгрузки), которые уже представлены плоскими карточками.
- **Итоговое каноническое число товаров не фиксируется исследованием** — это решение модели
  данных (см. `DR-09`). Ориентир: **≈49 канонических товаров**, ковши дополнительно раскрываются
  вариантами по типу техники.

Для **каждого** товара в `data/content-inventory.json` сохранён `sourceUrl` (проверено скриптом:
0 товаров без `sourceUrl`).

Что удалось снять по товарам: H1/название, диапазон цены и (частично) прайс по вариантам,
наличие таблицы характеристик и заголовки её столбцов, наличие секции «ВИДЕО», фрагменты
описания/агрегатирования. Полные строки спец-таблиц и полные тексты — **NOT VERIFIED** (см. §6).

## 6. Что NOT VERIFIED

- **`<title>`, meta description, canonical, og:*** — для **всех** страниц. Инструмент конвертирует
  страницу в Markdown до извлечения, `<head>` теряется. В инвентаре эти поля = `null`.
- **Полные строки спец-таблиц** для большинства товаров (сняты только заголовки столбцов и
  диапазоны цен; полные строки — для 5 карточек).
- **Полные тексты** блоков ОПИСАНИЕ / ПРЕИМУЩЕСТВА / АГРЕГАТИРОВАНИЕ — только фрагменты.
- **Точные списки совместимого оборудования** на витринах типов техники — не отделяются от
  общего меню каталога. Связи товар↔тип техники в инвентаре выведены из блоков
  «АГРЕГАТИРОВАНИЕ» карточек → **PARTIALLY VERIFIED**.
- **Платформа и URL видео** (YouTube/RuTube/VK) на 6 карточках с секцией «ВИДЕО».
- **Полный перечень изображений и alt-текстов** — не собран. `data/asset-manifest.json`
  содержит только 2 подтверждённых ассета (логотип, placeholder) + инструкцию, как достроить
  манифест по сырому HTML.
- **PDF/DOC** — на просмотренных страницах не найдено ни одной ссылки; полнота охвата не гарантирована.
- **Кандидаты в битые ссылки** на витринах (6 URL дочерних ковшей → HTTP 404): не подтверждено,
  присутствуют ли они в сыром HTML сайта или это артефакт извлечения. См.
  `content-inventory.json → candidateBrokenLinksOnHubPages`.
- **Поля форм** (Имя/Телефон/Email/…) — в извлечении не подписаны, фактический состав не подтверждён.
- **Содержимое `/menu`, `/footer`, `/pop-up`, `/error`** как отдельных блоков — просмотрены частично.
- **Точный объём и текст** политики конфиденциальности.

## 7. Аудит первого прохода (второй проход — запрос №4)

- **Дубль «Крюковой подвес»** (`/kryukovoj-podves` ↔ `/kruykovoi-podves`) — подтверждён сверкой

- **`sitemap-store.xml`** — 3 записи оказались демо-товарами Tilda (apples/pears/bananas), исключены.
- **Расхождения цен «заголовок vs таблица»** (DR-12) — обнаружены при поштучном разборе карточек.
- **Единицы «см» на `/lulka`** и **ошибка текста на `/navesnaya-dorognaya-freza`** — зафиксированы как DR-11, DR-08.

### 7.2 Что исправлено в инвентаре

- Добавлена `/privacy`; `/page63841391.html` помечена `duplicate-product`.
- Дубликаты «Крюковой подвес» разведены как `p-kryukovoj-podves` / `p-kruykovoi-podves` со
  ссылками `duplicateOf` и флагом `dataReviewRequired`.
- Все внутренние ссылки в инвентаре приведены к **каноническим slug из `sitemap.xml`**;
  ненадёжные/404-слаги вынесены в отдельный раздел `candidateBrokenLinksOnHubPages` и **не**
  используются как `sourceUrl` товаров.
- Демо-товары `sitemap-store.xml` вынесены отдельно с вердиктом «не включать в каталог».
- Проставлены `machineTypes[]` каждому товару (на основе блоков «АГРЕГАТИРОВАНИЕ», помечено PARTIALLY VERIFIED).
- 12 пунктов `DATA_REVIEW_REQUIRED` с указанием URL-источников (оба конфликтующих значения сохраняются).

### 7.3 Итоговое количество страниц

**99** уникальных известных страниц (98 в `sitemap.xml` + `/privacy`). Демо-`sitemap-store.xml`
(3) и служебные блоки Tilda не считаются контентом.

### 7.4 Итоговое количество товаров

- **77** страниц товаров (50 плоских + 27 ковшовых, привязанных к типу техники).
- **≈49** канонических товаров после слияния дубля «крюковой подвес» и с учётом того, что
  27 ковшовых страниц — варианты уже существующих типов ковшей. Финальная канонизация — `DR-09`.

### 7.5 DATA_REVIEW_REQUIRED (после аудита)

12 пунктов, DR-01 … DR-12 (см. §5 и `content-inventory.json`). Новых бизнес-конфликтов,
разрешённых догадкой, — **нет**.

### 7.6 NOT VERIFIED (после аудита)

Без изменений относительно §6. Ключевое ограничение — инструмент отдаёт не сырой HTML, а
краткое извлечение, поэтому метаданные `<head>`, полные таблицы, полный перечень ассетов и
достоверность внутренних `href` на витринах остаются непроверяемыми этим методом. Для их
закрытия нужен доступ к сырому HTML/DOM или к экспорту Tilda.
