# DESIGN PLAN — дизайн-направление и техническая архитектура прототипа

Дата: 2026-08-30. Frontend-код не создавался, зависимости не устанавливались.

Основание: `docs/REFERENCES.md` §6–§7 (направление «Технический лист»), `.claude/rules/design.md`,
`.claude/rules/content-integrity.md`. Ни один reference не копируется — заимствованы только
структурные и поведенческие принципы.

Всё, что касается фирменного стиля СТ-ТЕХНИКС, помечено **PROVISIONAL**: логотип локально
отсутствует, фирменные цвета и шрифты не подтверждены.

---

## 1. Направление

Сайт ведёт себя как **хорошо свёрстанный технический лист производителя**. Единица смысла —
строка данных: параметр, значение, единица, совместимость, цена, источник.

Пять принципов (из `REFERENCES.md` §7), с уточнением по итогам этого этапа:

1. **Данные важнее декора.** Первый экран страницы товара показывает название, цену и
   характеристики, а не слоган.
2. **Пустота честнее выдумки.** Нет данных — нет блока. Не «уточняется», не прочерк в рамке,
   а отсутствие секции.
3. **Две равноправные оси входа.** Каталог и подбор по типу техники представлены на главной
   одинаковым весом.
4. **Оборудование — единственный герой.** Только реальные фотографии; при их отсутствии —
   явная техническая заглушка.
5. **Промышленная сдержанность.** Плотная сетка, прямые углы, тонкие линии, минимум теней.

**Уточнение, добавленное на этом этапе:** «технический лист» не означает «серый документ».
Выразительность создаётся тремя средствами — крупным фото оборудования, резким контрастом
размеров в типографике (H1 48 против body 16) и одной тёмной зоной на странице. Всё остальное
остаётся спокойным. Сухость допустима внутри таблиц, но не на уровне страницы.

## 2. Сетка, контейнер, ритм

| Параметр | Desktop | Tablet | Mobile |
|---|---|---|---|
| Контейнер | 1280 | 100 % − 2×32 | 343 |
| Колонок | 12 | 8 | 4 |
| Gutter | 24 | 20 | 16 |
| Внешние поля | 80 | 32 | 16 |

Точки перелома: **1280 / 1024 / 768 / 375**.
Вертикальный ритм кратен 8. Отступы между секциями: 64–96 desktop, 40–56 mobile.
Шкала отступов: 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96.

Каталог: 3 карточки в ряд (≥1024), 2 (768–1023), 1 (<768).
Страница товара: 8 колонок контент + 4 колонки липкая панель запроса (≥1024); одна колонка ниже.

## 3. Типографика

| Роль | Desktop | Mobile | Начертание |
|---|---|---|---|
| H1 | 48 / 1.1 | 32 / 1.15 | плотный дисплейный |
| H2 | 32 / 1.2 | 24 / 1.25 | плотный дисплейный |
| H3 | 24 / 1.3 | 20 / 1.3 | плотный дисплейный |
| Body | 16 / 1.6 | 16 / 1.6 | текстовой |
| Small / подписи | 14 / 1.5 | 14 / 1.5 | текстовой |
| Таблица | 15 / 1.4 | 14 / 1.4 | текстовой, `tabular-nums` |
| Цена крупная | 32 | 28 | дисплейный, `tabular-nums` |

Требования к гарнитурам: **полная кириллица**, открытая лицензия, self-hosted (внешних запросов
к шрифтовым CDN нет), наличие табличных цифр.

**PROVISIONAL, требует утверждения:** дисплейный — *IBM Plex Sans Condensed*, текстовой — *Inter*.
Альтернатива для текста — *Golos Text*. Обоснование: инженерный, не «маркетинговый» характер,
надёжная кириллица, узкий дисплейный хорошо держит длинные русские названия
(«Планировщик-выравниватель грунта»).

Правила: заголовки без разрядки и без капители на длинных названиях; переносы не запрещены;
названия товаров не обрезаются многоточием в середине слова; `font-variant-numeric: tabular-nums`
обязателен для всех цен и таблиц, иначе колонки «пляшут».

## 4. Цвет — PROVISIONAL, функциональная палитра

Фирменные цвета не подтверждены. Палитра функциональная: заменяется на фирменную правкой значений
CSS-переменных, без переписывания компонентов.

| Токен | Роль |
|---|---|
| `--bg` | Основной фон — белый |
| `--bg-muted` | Подложка карточек, чётные строки таблиц — очень светлый нейтрально-серый |
| `--text` | Основной текст — почти-чёрный нейтральный |
| `--text-muted` | Вторичный текст, подписи — средний серый |
| `--line` | Линии и рамки — светло-серый, 1 px |
| `--accent` | **Один** акцент: основные кнопки, активные состояния, ключевые метки |
| `--accent-contrast` | Текст на акценте |
| `--dark` | Тёмная зона: футер и одна акцентная полоса на странице |

Правила: акцент занимает **≤ 5 %** площади экрана; заливок акцентом на половину экрана нет;
градиентов нет; статусные цвета (ошибка формы) берутся из того же нейтрального ряда + один красный.

**PROVISIONAL:** в качестве акцента предлагается насыщенный индустриальный оранжевый — типичный
для спецтехники и хорошо читаемый на белом. Это **не** фирменный цвет СТ-ТЕХНИКС. Как только в
проекте появится файл логотипа, акцент выводится из него и меняется в одной переменной.

Контраст: текст ≥ 4.5:1, крупный текст и элементы интерфейса ≥ 3:1.

## 5. Изображения

- Только реальные фотографии оборудования, техники и производства.
- Нет фото → **явная техническая заглушка**: нейтральный фон, контурный знак, подпись
  «Фото готовится». Заглушка обязана читаться как заглушка.
- Запрещено: AI-сгенерированные фото техники, стоковые люди, чужие фотографии как фото продукции
  СТ-ТЕХНИКС (`content-integrity.md`).
- Пропорции: карточка 4:3, галерея 3:2, hero 21:9 (desktop) / 4:3 (mobile), `object-fit: cover`.
- `loading="lazy"` вне первого экрана, явные `width`/`height` против сдвигов вёрстки,
  осмысленный `alt`; если alt не подтверждён — генерируется из названия товара.
- Для каждого использованного ассета сохраняется исходный URL.

## 6. Компоненты

**Формы и радиусы.** Один радиус на весь сайт — 2 px (кнопки, поля, карточки, изображения).
Тени: только на выпадающих элементах (drawer, модалка), не на карточках. Рамки 1 px `--line`.

**Кнопки.**

| Уровень | Вид | Применение |
|---|---|---|
| Primary | заливка `--accent` | «Запросить цену» — **одна на экран** |
| Secondary | контур 1 px | «Перейти в каталог», «Показать N товаров» |
| Tertiary | текст с подчёркиванием при наведении | «Сбросить всё», «Ещё N типов» |

Высота 48 desktop / 44 mobile; видимый фокус обязателен во всех состояниях.

**Карточка товара.** Прямоугольная, рамка 1 px, без тени; при наведении — смена цвета рамки и
подчёркивание названия, без подъёма и масштабирования. Вся карточка — одна ссылка.
Внутри: фото → бейджи → название → 2–3 строки «параметр — значение» → цена → метки техники.

**Таблицы — несущий элемент.**

- шапка на `--bg-muted`, нижняя граница 1 px, зебра чётных строк;
- числа выравниваются вправо и набираются табличными цифрами, текст — влево;
- горизонтальный скролл **внутри своего контейнера** (`overflow-x: auto`), страница по горизонтали
  не едет никогда;
- первая колонка липкая на мобильном, чтобы модель/ширина оставались видны;
- значения не обрезаются и не сокращаются;
- у таблицы есть `<caption>` или заголовок над ней и `scope` у заголовков колонок.

**Фасеты.** Группы с заголовками, чекбоксы, счётчик у каждого значения; на мобильном — drawer
снизу с кнопкой «Показать N товаров». Чипы применённых фильтров — прямоугольные, с крестиком,
горизонтальный скролл на мобильном.

**Header.** Высота 72 desktop / 56 mobile, фон `--bg`, нижняя граница 1 px, липкий при прокрутке.
Логотип, 4 пункта меню, телефон, primary CTA. Mobile — полноэкранное меню, фокус запирается внутри,
Esc закрывает.

**Footer.** Зона `--dark`: контакты, «Каталог» (8 категорий), «Тип техники» (7 типов), копирайт
в формулировке источника. **Ссылки на политику конфиденциальности нет** — подтверждённого текста
не существует; ссылка появится вместе с ним. Чекбокс согласия в mock-формах остаётся текстом
без ссылки на несуществующую страницу.

## 7. Адаптивность

| Что | Поведение |
|---|---|
| Header | 4 пункта → бургер + полноэкранное меню (<768) |
| Каталог | 3 → 2 → 1 колонка |
| Фасеты | боковая колонка → drawer с липкой кнопкой «Фильтры (N)» |
| Товар | 2 колонки + липкая панель → одна колонка + липкая нижняя полоса «от X ₽ · Запросить цену» |
| Таблицы | скролл в контейнере + липкая первая колонка |
| Галерея | миниатюры сбоку → лента со свайпом и точками |
| Длинные названия | переносятся, максимум 2 строки в карточке, без обрезки в середине слова |

Проверяется на 1440 / 1280 / 1024 / 768 / 390 / 360.

---

## 8. Доступность

Семантический HTML (`<nav>`, `<main>`, `<table>`, `<button>`, `<label>`); одна `<h1>` на страницу и
непрерывная иерархия заголовков; видимый фокус (2 px контур с отступом); полное управление с
клавиатуры для меню, фасетов, drawer и галереи; ловушка фокуса и Esc в модальных элементах;
`aria-live` для счётчика результатов; зоны нажатия ≥ 44 px; контраст ≥ 4.5:1; у всех полей формы
подписи, у ошибок — текстовое сообщение, а не только цвет.

---

## 9. Движение

Только функциональное: открытие drawer и меню, переключение изображения, раскрытие аккордеона,
смена состояния кнопки. Длительность ≤ 200 мс, easing один на весь сайт.
Нет: появления при прокрутке, параллакса, счётчиков цифр, каруселей-автоплея.
`prefers-reduced-motion: reduce` отключает все переходы.

## 10. Frontend stack

**Выбрано: Astro + TypeScript, `output: 'static'`, обычный CSS с custom properties.**

Почему:

- весь контент известен на этапе сборки → 69 страниц генерируются из локального JSON
  (`getStaticPaths` для 49 товаров, 8 категорий, 7 типов техники);
- по умолчанию в браузер не уезжает JS; интерактив — точечные острова: фасеты каталога, галерея,
  мобильное меню, mock-форма;
- слой данных изолирован (`src/data/*.ts`) → позже подменяется на CMS/API без переписывания
  страниц и компонентов;
- результат сборки — статические файлы, никакого сервера, что соответствует «прототип, не
  инфраструктура»;
- TypeScript даёт проверку модели данных из `DATA_MODEL.md` на этапе сборки.

Что **не** выбрано:

| Вариант | Почему нет |
|---|---|
| Next.js (App Router) | React в рантайме и слой абстракций, не нужные 69 статическим страницам; больше конфигурации |
| Vite + React SPA | Теряется статический HTML: каталог и товары должны существовать как обычные страницы |
| 11ty | Хорош для контента, но слабее TS-типизация и компонентная модель для фасетов и галереи |
| Без сборки, чистый HTML | 69 страниц и повторяющиеся блоки пришлось бы дублировать вручную; цена правки дизайна недопустимо высокая |
| CSS-фреймворк (Tailwind/UI-kit) | Дизайн-система здесь маленькая и своя; чужие токены и компоненты тянут в сторону generic-вида |

Не создаётся: backend, CMS, база данных, авторизация, CRM, интеграции, онлайн-оплата.
Все формы — **mock**, без сетевых запросов: отправка показывает состояние успеха локально.

Планируемая структура:

```
src/
  data/          getProducts(), getProduct(slug), getVisibleMachineTypes(), getCategories()
  types/         catalog.ts — типы из DATA_MODEL.md
  components/    Header, Footer, Breadcrumbs, ProductCard, SpecTable, FacetPanel,
                 Gallery, RequestForm, Placeholder
  layouts/       Base.astro, Page.astro
  pages/         index, catalog/index, catalog/category/[category], catalog/[product],
                 machines/index, machines/[machineType], oplata-i-dostavka, contacts,
                 _data-review
  styles/        tokens.css, base.css
data/catalog/    products.json, variants.json, categories.json, machine-types.json,
                 assets.json, data-review.json
scripts/         validate-catalog.mjs
public/images/   реальные фотографии, когда будут добавлены локально
```

**Как подключить настоящий backend/CMS позже.** Страницы обращаются только к функциям из
`src/data/*.ts`. Замена локального JSON на запрос к CMS (Strapi, Directus, 1С-выгрузка) затрагивает
только эти функции; типы, компоненты и маршруты не меняются. Поля `sourceUrl`, `provenance`,
`confirmed` и `dataReview` переносятся в CMS как часть модели, а не как временные пометки.

**Зависимости на этом этапе не устанавливались.** Установка Astro — отдельный шаг после
подтверждения пользователем.

## 11. PROVISIONAL и NOT VERIFIED

**PROVISIONAL (требует утверждения владельцем):**

1. Пара шрифтов (IBM Plex Sans Condensed + Inter / Golos Text).
2. Акцентный цвет и вся палитра — функциональная, не фирменная.
3. Названия и состав 8 категорий каталога.
4. Правило отбора 8 товаров на главную (порядок каталога-источника).

**NOT VERIFIED:**

- Фирменные цвета и шрифты СТ-ТЕХНИКС — не извлекались; файл логотипа локально отсутствует.
- Фотографии оборудования — локальных файлов нет; браузерные инструменты не используются,
  скачивание с сайта не выполнялось. До появления файлов весь визуальный слой работает на
  заглушках, и оценить дизайн «по-настоящему» нельзя.
- Живые сайты референсов не открывались; выводы сделаны по статичным скриншотам
  (`REFERENCES.md` §8).
- Ни один экран прототипа не проверялся в браузере — **NOT VERIFIED: browser** (кода ещё нет).
