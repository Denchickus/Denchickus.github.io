## 4. Ловушки, на которых уже спотыкались

Это не теория — каждый пункт стоил реальной отладки в запросе №30.

* **`writeUrl()` в `CatalogView.astro` обязан сохранять `location.hash`.** Он вызывается уже на
  первой загрузке; без сохранения hash `/catalog#search` из шапки перестаёт фокусировать поле
  поиска. Ловится только в браузере.
* **Нижняя CTA-полоса товара пересекается с плавающей кнопкой Telegram** (`z-index:60`), если не
  зарезервировать место справа. Размер виджета разный: 60px/right:28px до 768px и 50px/right:16px
  ниже. Проверять `getBoundingClientRect()`, а не глазами.
* **Липкая боковая панель и нижняя полоса должны покрывать диапазоны без разрыва.** Панель
  скрыта на ≤1024px, полоса включена на ≤1024px. Раньше был провал 769–1024px без цены и CTA.
* **Таблицы источника используют `colspan`/`rowspan`, а часть `<tr>` не закрыта.** Строки режутся
  по открывающему `<tr>`, ячейки сохраняются с атрибутами. Наивный разбор терял 165 строк.
* **Node не резолвит extensionless относительные импорты в `.ts`.** В тестах — `../src/data/catalog.ts`,
  JSON-импорты — `with { type: 'json' }`.
* **Playwright: `target` — это ref из снапшота** (`f1e52`), а не описание элемента; описание
  идёт в `element`. Refs протухают после перерисовки DOM — брать свежий снапшот.
* **Проверять рендер грепом по `dist/` можно только с учётом `data-astro-cid-*`** — Astro
  дописывает атрибут scoped-стилей, и `/<h2>Описание/` не сматчится.

## 5. Открытые DATA_REVIEW (не решать самостоятельно)

В `data/content-inventory.json → dataReviewRequired` сейчас 15 записей: DR-01…DR-12, DR-14,
DR-15, DR-16.

> **Расхождение, замеченное при передаче (не исправлялось).** `DR-13` существует только в
> документации — он был добавлен на этапе проектирования в `docs/DATA_MODEL.md` §8 (тоннажные
> ковши на мини-экскаватор: самостоятельный товар или варианты «Ковша универсального») и в
> инвентарь так и не перенесён. Поэтому счёт DR по документам и по данным расходится, а
> `SITE_STRUCTURE.md` §8 говорит «DR-01…DR-13». Само содержание DR-13 живое и актуальное —
> оно напрямую касается вариантов, реализованных в запросе №30. Перенести его в инвентарь
> (или сознательно оставить только в документе) — решение пользователя, не техническая правка.

Новые за этап:

* **DR-15** — флаг `hasVideo` у 6 товаров не подтверждается содержимым страниц: ни `<video>`,
  ни `<iframe>`, ни ссылок YouTube/Rutube/VK. Блок видео нигде не рендерится. Флаг не менялся.
* **DR-16** — у `kovsh-obshchestroitelnyj` и `kovsh-universalnyj` на канонической странице есть
  таблицы для типов техники, у которых нет отдельной bucket-страницы (и, значит, нет
  `ProductVariant`). Показаны блоком «Дополнительные конфигурации» — но только когда подпись
  таблицы явно называет **подтверждённый** тип техники. Это правило само отсекло соседнюю
  таблицу цены неподтверждённого «Экскаватора»; на это есть тест, не ослаблять его.

Вопрос владельцу по DR-16: сделать эти конфигурации полноценными вариантами или оставить
отдельным блоком.
